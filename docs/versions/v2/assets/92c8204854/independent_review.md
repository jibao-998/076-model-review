# V2 独立复核记录

复核对象：本目录当前生成的装配、骨架和爆炸三个 3dm，以及 `source/build_assembly.py`、参数文件和离线网页源码。复核日期：2026-10-17。除本记录外，复核未修改模型或生成脚本。

结论：前轮发现的托条与肋骨实体交叠、原生爆炸命名视图裁切、部分参数未驱动几何的问题已收口。本次检查未发现阻止概念装配评审的遗留问题；此结论不构成制造放行。

## 本轮独立复验

| 项目 | 方法与结果 |
|---|---|
| 板件互相干涉 | 从当前 `assembly_scene.json` 重建龙骨、肋骨、纵梁、内部甲板、托条、飞行甲板及升降机平台的封闭网格；对包围盒存在正体积重叠的54对候选执行 trimesh/manifold 实体布尔。正交叠体积阈值为 0.0001 mm³，结果为零处交叠。此检查排除零厚度蒙皮、预留包络和外观上层建筑。 |
| 原生视图裁切 | 回读三个 3dm，各有5个有效命名视图。用每个文件可见原生对象的保守包围盒角点，独立投影到保存的相机坐标及视锥，检查左右、上下及近远裁剪。15个视图全部通过。各文件最不利归一化投影范围：装配0.869290、骨架0.862069、爆炸0.955706，均小于1。原爆炸视图上层建筑顶部裁切问题未残留。 |
| 母面保护 | 直接比较当前装配文件的30片前/后体原生NURBS分块与输入原生母面；每片7×7，共1470个同参数点。最大距离 5.686124902173432×10⁻¹³ mm。该结果是抽样证据，结合源码中的精确插节点切分使用，不是实船外形精度声明。 |
| 横艉保护 | 当前 `SKIN_TRANSOM` 与输入 `TRANSOM_REFERENCE_CAP` 的原生 `Geometry.Encode()` 完全相等。 |
| 旧版保护 | 重新计算 `input_hashes.json` 登记的三个原文件SHA256，全部与登记值相同，见下表。 |
| 参数驱动 | 源码已用 `RESERVED_VOLUMES` 同时生成预留包络及肋骨让位，用 `STRINGER_X/Z` 生成纵梁及互补槽。未用的 `KEEL_SLOT_MID_Z` 已删除。升降机井先从平台参数重新派生，再写入 `resolved_parameters.json`；槽宽按厚度加总配合余量重新计算。 |
| 冻结参数 | 构建入口在生成几何前明确校验 LENGTH=800、MATERIAL_THICKNESS=3、DECK_BOTTOM_Z=76、REFERENCE_WL_Z=32；改动这些冻结值需要协同重设，不能视为已支持的任意参数变体。此项为代码路径复核，未修改输入文件做参数变异构建。 |
| 预留净空 | 当前构建的 `reserved_clearance.json` 为零交叠；已核对源码确实计算轴向预留盒与板件局部平面的多边形/厚度交集。本轮另行执行的54对布尔属于板件互查，二者检查范围不同。 |
| 离线性 | 生成入口使用包内相对路径，网页生成器将 three.js、OrbitControls 和场景数据嵌入HTML。未发现外部运行时数据请求依赖；重建仍需事先安装 requirements 中的Python依赖。 |

前轮还曾按肋骨实体前、后两侧X位置重新取当前母面截面，检查全部肋骨网格顶点，未发现穿出零厚度母面的顶点。该证据只覆盖当前参考外形，不等于已为3 mm实物蒙皮留足余量。

本轮未操作原生Rhino桌面：显示效果、实际切换命名视图、Join/裸边、法向与水密检查均为 **NOT_CHECKED**。本记录中的相机检查是保存文件的数学投影检查，不能称为Rhino界面测试。网页交互的既有检查见 `browser_validation.json`；本轮未重新执行独立浏览器交互测试。
